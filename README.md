# ピックルボール大会運営システム

自分が主催する大会だけで使う、**参加者のアカウント登録が不要**な大会運営Webシステムです。
リーグ戦から決勝トーナメントまで1つのサイトで完結します。

- 参加者はURLを開くだけ。ログイン・アプリのインストール不要
- 各チームの代表者がスマホから試合結果を入力できる
- 結果が入ると順位表・トーナメント表・進行表が**自動で再計算され、他の人のスマホにも自動反映**
- 主催者用の管理画面だけパスワードで保護

## 1. システム構成

```
  参加者のスマホ                          主催者のPC / スマホ
       │                                        │
       │ ①読み取り（Realtime購読）               │ Cookie認証
       │   anonキー・読み取り専用                │
       ▼                                        ▼
  ┌─────────────────┐              ┌──────────────────┐
  │  Supabase       │◀────────────│  Next.js         │
  │  PostgreSQL     │  service_role│  ・参加者ページ   │
  │  + Realtime     │   （書き込み）│  ・管理画面       │
  └─────────────────┘              │  ・API Routes    │
       ▲                            └──────────────────┘
       │ ②書き込みは必ずサーバー経由（POST /api/...）        ▲
       └───────────────────────────────────────────────────┘
```

設計上のポイント（トラブルを避けるための判断）:

| 決めたこと | 理由 |
| --- | --- |
| **書き込みはすべてNext.jsのAPI経由** | 参加者のブラウザに書き込み権限のあるキーを渡さない。スコア検証・勝者判定・次ラウンドへの繰り上げを1箇所（サーバー）に集約でき、矛盾した状態になりにくい |
| **読み取りはSupabaseのanonキー + RLSで読み取り専用** | Realtimeをそのまま使えるので「他の人のスマホにすぐ反映」が追加コストなしで実現できる |
| **参加者は認証なし** | ITに詳しくない参加者でも、URLを開くだけで使える。悪用リスクは「主催者がいつでも修正できる」ことで担保 |
| **管理画面はパスワード1つ** | ユーザー管理・メール送信が不要。主催者1人の運用ならこれで十分 |
| **順位計算とトーナメント生成は独立した純粋関数** | 同率時のルール変更やチーム数変更に、画面を触らず対応できる（`src/lib/standings.ts` / `src/lib/bracket.ts`）|

## 2. 使用技術

| 役割 | 技術 | 費用 |
| --- | --- | --- |
| フロント + サーバー | Next.js 15 (App Router) / React 19 / TypeScript | — |
| スタイル | Tailwind CSS | — |
| データベース・リアルタイム配信 | Supabase (PostgreSQL + Realtime) | 無料枠で十分 |
| ホスティング | Vercel | 無料枠（Hobby）で十分 |

1日1大会・16チーム規模ならデータ量・アクセス数ともに無料枠に余裕で収まります。
**追加で必要な有料サービスはありません。**

> なぜこの構成か：「他の端末にすぐ反映」を自前で作るとWebSocketサーバーの用意が必要になりますが、
> SupabaseのRealtimeを使えばテーブルの変更通知がそのまま届くため、MVPの実装量が大きく減ります。
> DBファイル方式（SQLiteなど）はVercelのようなサーバーレス環境では永続化できないため採用していません。

## 3. データベース構造

`supabase/schema.sql` がそのまま定義ファイルです。

| テーブル | 役割 | 主なカラム |
| --- | --- | --- |
| `tournaments` | 大会情報と大会設定（1行だけ使う） | `name` `event_date` `venue` `note` `league_count` `teams_per_league` `start_time` `minutes_per_match` `courts` `tiebreakers` **`bracket_tiers`** `phase` |
| `leagues` | A / B / C / Dリーグ | `name` `sort_order` |
| `teams` | チーム | `name` `members` `league_id` `sort_order` |
| `matches` | 試合（リーグ戦・トーナメント共通） | `stage` `league_id` **`tier_key`** `round` `bracket_index` `is_third_place` `match_no` `court` `scheduled_at` `status` `team_a_id` `team_b_id` `team_a_label` `team_b_label` `score_a` `score_b` `winner_team_id` `next_match_id` `next_slot` `loser_next_match_id` `loser_next_slot` |
| `match_events` | 結果の履歴（誰がいつ何点で登録したか） | `action` `score_a` `score_b` `actor` `created_at` |

ポイント:

- **リーグ戦とトーナメントを同じ `matches` テーブルで扱う**ので、進行表・結果入力の仕組みが1つで済みます。
- **順位別トーナメント（A級/B級/C級）は `matches.tier_key` で区別**します。級の定義は
  `tournaments.bracket_tiers` にJSONで入っており、
  `{ 級名, 対象順位の範囲, 3位決定戦の有無 }` の配列です。級を増やしてもテーブル定義は変わりません。
- トーナメントの試合は `next_match_id` / `next_slot` で「勝ったらどこへ行くか」を持っています。
  3位決定戦は `loser_next_match_id` で準決勝の敗者とつながります。
- 対戦相手が未確定のトーナメント試合は、`team_a_label` に `Aリーグ1位` `準決勝1の勝者` などの
  文字列が入り、決まり次第 `team_a_id` が埋まります。
- **順位表はDBに保存しません。** 試合結果から毎回計算するので、結果を直せば順位も必ず正しくなります。
- `match_events` は監査ログです。「誰が入力したか分からない」問題を防ぎ、将来の承認機能の土台になります。

### 順位の決め方（変更可能）

`tournaments.tiebreakers` の配列順に比較します。初期値は次のとおりです。

1. 勝数
2. 得失点差（得点 − 失点）
3. 総得点

管理画面の「大会情報」→「順位の決め方」から、**上下ボタンで並べ替え・条件の追加/削除**ができます。
選べる条件：勝数 / 勝率 / 得失点差 / 総得点 / 総失点の少なさ / 直接対決の結果。
計算処理は `src/lib/standings.ts` に独立しているため、独自ルールを足したい場合もそのファイルだけ変更すれば済みます。

## 5. ユーザー操作フロー

### 参加者（試合が終わったとき）

```
トップページを開く
   └─「試合結果を入力する」をタップ
        └─ 自分のチームの試合をタップ（チーム名で検索も可）
             └─ ＋−ボタンでスコアを入力（例 11 - 7）
                  └─「結果を送信する」
                       └─ 確認画面
                          「サンダーズ 11 - 7 レイクブリーズ
                            この結果で登録しますか？」
                            ├─ はい → 登録完了。順位表・トーナメント表が即更新
                            └─ いいえ → 入力画面に戻る
```

- 誤入力対策として**必ず確認画面**を通ります。
- 同点は登録できません（勝者が決まらないため）。
- 間違えた場合は同じ画面から入力し直せます（上書き）。主催者もいつでも修正できます。

### 主催者（準備）

```
/admin にアクセス → パスワードでログイン
 ① 大会情報を設定（大会名・日付・会場・コート番号・開始時刻）
 ② チームを登録（まとめて貼り付け）→「登録順に自動で振り分け」でA〜Dリーグへ
 ③「対戦・結果」→「リーグ戦の対戦カードを作成する」
     ・各リーグの総当たり表と、時間・コートが自動で入る
 ④「進行表」で時間・コート・順番を微調整（必要なら）
 ⑤ 当日を迎える
 ⑥ 予選終了後「トーナメント」→「トーナメント表を作成」
```

## 6. 16チーム大会の進行方法

### 予選リーグ

- 4リーグ（A・B・C・D）× 各4チーム
- 各リーグ総当たり = 1リーグ6試合 → **合計24試合**
- コート4面・1試合20分の設定なら **6時間帯（09:00〜10:40）で予選が終わります**
- 対戦カードはサークル法で生成するため、**同じチームが同じ時間帯に2試合入ることはありません**
  （＝連戦になりにくい進行順）

### 予選 → 順位別トーナメント（A級 / B級 / C級）

予選の順位ごとに**別々のトーナメント**を作ります。**全16チームがトーナメントに出場**するので、
早く負けたチームも最後まで試合があります。

| 級 | 対象 | 出場 | 試合数 |
| --- | --- | --- | --- |
| **A級** | 各リーグ **1〜2位** | 8チーム | 8試合（準々決勝〜決勝＋3位決定戦） |
| **B級** | 各リーグ **3位** | 4チーム | 3試合（準決勝〜決勝） |
| **C級** | 各リーグ **4位** | 4チーム | 3試合（準決勝〜決勝） |

この「級」は管理画面の **「大会情報」→「順位別トーナメント（級）」** から変更できます。
級の追加・削除、対象順位の変更、級ごとの3位決定戦の有無を設定できます。

#### A級の組み合わせ

同じリーグ同士が早い段階で当たらないよう、自動でクロス配置します。

```
準々決勝                  準決勝              決勝
Aリーグ1位 ─┐
Bリーグ2位 ─┴─┐
              ├─┐
Dリーグ1位 ─┐ │ │
Cリーグ2位 ─┴─┘ │
                 ├── A級優勝
Bリーグ1位 ─┐   │
Aリーグ2位 ─┴─┐ │
              ├─┘
Cリーグ1位 ─┐ │
Dリーグ2位 ─┴─┘

＋ 3位決定戦（準決勝の敗者同士）
```

- 同じリーグの2チームは**決勝まで当たりません**（初戦・準決勝で再戦しない配置）

#### B級・C級の組み合わせ

各リーグから1チームずつなので、そもそも同リーグ対決は起きません。

```
準決勝              決勝
Aリーグ3位 ─┐
Dリーグ3位 ─┴─┐
              ├── B級優勝
Bリーグ3位 ─┐ │
Cリーグ3位 ─┴─┘
```

#### 全体

- トーナメントは **合計14試合**（A級8 + B級3 + C級3）
- 大会全体で **38試合**
- 各級は完全に独立しています。A級の結果がB級・C級に影響することはありません
- 結果を入力すると勝者が自動で次の試合へ進みます
- **結果を修正した場合、その先のラウンドの結果は自動で取り消され、組み合わせが作り直されます**
  （矛盾した状態が残りません）

### 想定タイムテーブル例（コート4面 / 1試合20分）

| 時間 | 内容 |
| --- | --- |
| 09:00 - 10:40 | 予選リーグ 24試合（6時間帯） |
| 10:40 - 11:00 | 休憩・順位確定・トーナメント表作成 |
| 11:00 - 11:20 | A級 準々決勝 4試合 |
| 11:20 - 11:40 | B級・C級 準決勝 4試合 |
| 11:40 - 12:00 | A級 準決勝 2試合 / B級・C級 決勝 |
| 12:00 - 12:20 | A級 3位決定戦・決勝 |

各級の同じラウンドが同じ時間帯に並ぶように自動割り当てされるので、コートが空きません。

## 7. Supabaseの初期設定

所要時間: 約10分。

1. **アカウント作成 / プロジェクト作成**
   - <https://supabase.com> にアクセスしてサインアップ（無料）
   - `New project` をクリック
   - Name: 任意（例 `pickleball-tournament`）
   - Database Password: 自動生成でOK（**メモしておく**）
   - Region: `Northeast Asia (Tokyo)` を選ぶと国内から速いです
   - `Create new project` → 1〜2分待つ

2. **テーブルを作る**
   - 左メニューの `SQL Editor` を開く
   - `New query` をクリック
   - このリポジトリの **`supabase/schema.sql` の中身をすべてコピーして貼り付け**
   - 右下の `Run` を押す → `Success` と出れば完了
   - （何度実行しても壊れないので、やり直しても大丈夫です）

   > **すでに一度 `schema.sql` を実行済みの場合**
   > 順位別トーナメント（A級/B級/C級）に対応するため、列を2つ追加しています。
   > `supabase/migration_001_bracket_tiers.sql` を同じ手順で1回実行してください。
   > **既存のチーム・試合・結果は削除されません。**
   > （これから初めて `schema.sql` を実行する場合は、マイグレーションは不要です）

3. **キーを3つコピーする**
   - 左下の `Project Settings` → `API`（新しいUIでは `Configuration` → `API Keys`）
   - 次の3つを控えます。

     | 項目 | 対応する環境変数 | 扱い |
     | --- | --- | --- |
     | Project URL | `NEXT_PUBLIC_SUPABASE_URL` | 公開OK |
     | `anon` `public` キー | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 公開OK（読み取り専用） |
     | `service_role` `secret` キー | `SUPABASE_SERVICE_ROLE_KEY` | **絶対に公開しない** |

4. **（任意）Realtimeの確認**
   - `Database` → `Publications` → `supabase_realtime` に
     `tournaments` `leagues` `teams` `matches` が入っていることを確認
   - `schema.sql` が自動で追加しているので、通常は何もしなくてOKです
   - もし入っていなくても、20秒ごとの自動再取得で画面は更新されます

5. **（任意）練習用データを入れる**
   - 本番前に操作を練習したい場合、`SQL Editor` で `supabase/seed.sql` を実行すると
     16チーム・4リーグのサンプルが入ります
   - **既存のチーム・試合は削除されるので、本番の大会データが入った後は実行しないでください**

## 8. ローカルでの起動方法

必要なもの: Node.js 18.18 以上（20 以上を推奨）

```bash
# 1. 依存パッケージをインストール
npm install

# 2. 環境変数ファイルを作る
cp .env.example .env.local

# 3. .env.local をエディタで開いて、値を入れる
#    NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
#    NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
#    SUPABASE_SERVICE_ROLE_KEY=eyJ...
#    ADMIN_PASSWORD=好きなパスワード
#    ADMIN_SESSION_SECRET=（openssl rand -base64 32 の出力）

# 4. 開発サーバーを起動
npm run dev
```

- 参加者画面: <http://localhost:3000>
- 管理画面: <http://localhost:3000/admin>

同じWi-Fiのスマホから確認したい場合は `npm run dev -- -H 0.0.0.0` で起動し、
PCのローカルIP（例 `http://192.168.0.5:3000`）を開いてください。

その他のコマンド:

```bash
npm run build      # 本番ビルド
npm start          # ビルド結果の起動
npm run typecheck  # 型チェック
```

## 9. デプロイ方法（Vercel）

所要時間: 約10分。無料枠（Hobby）で運用できます。

1. このリポジトリをGitHubにpushする
2. <https://vercel.com> にGitHubアカウントでログイン
3. `Add New...` → `Project` → 対象リポジトリを `Import`
4. **Environment Variables** に次の5つを登録（Framework Presetは自動でNext.jsになります）

   | Name | Value |
   | --- | --- |
   | `NEXT_PUBLIC_SUPABASE_URL` | SupabaseのProject URL |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public キー |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role キー |
   | `ADMIN_PASSWORD` | 管理画面のパスワード |
   | `ADMIN_SESSION_SECRET` | ランダムな文字列 |

5. `Deploy` を押す → 数分で `https://xxxx.vercel.app` が発行されます
6. **参加者にはこのURLだけを共有**します（QRコードにしておくと当日スムーズです）

> 環境変数を後から変更した場合は、Vercelの `Deployments` から `Redeploy` してください。

## 10. 管理者パスワードの設定

### 設定方法

`ADMIN_PASSWORD` に設定した文字列が、そのまま管理画面のログインパスワードになります。

- ローカル: `.env.local` の `ADMIN_PASSWORD=...`
- 本番: Vercelの `Settings` → `Environment Variables` → `ADMIN_PASSWORD`

`ADMIN_SESSION_SECRET` はログイン状態を保持するCookieの署名に使います。
未設定でも動きますが、**本番では必ず設定してください**。生成例:

```bash
openssl rand -base64 32
```

### 仕組みと注意点

- ログインすると署名付きCookieが発行され、**12時間**有効です
- 管理画面（`/admin/*`）と管理API（`/api/admin/*`）はミドルウェアと各APIの二重チェックで保護されます
- パスワードを変更したい場合は環境変数を書き換えて再デプロイしてください
  （`ADMIN_SESSION_SECRET` を未設定にしている場合、パスワード変更で既存のログインは無効になります）
- 参加者側には認証がありません。**URLを知っている人は誰でも結果を入力できます**。
  身内の大会を前提とした割り切りで、代わりに主催者がいつでも修正できるようにしています。
  不安な場合は[今後の拡張ポイント](#14-今後の拡張ポイント)のPINコード方式を検討してください

---

## 11. 大会当日の使い方

### 前日までに（主催者）

1. `/admin` にログイン
2. **大会情報**: 大会名・開催日・会場・コート番号（例 `1, 2, 3, 4`）・開始時刻・1試合の持ち時間を設定
3. **チーム・リーグ分け**: 参加チームを「まとめて登録」に貼り付け（1行1チーム、`チーム名,メンバー` 形式も可）
4. 「登録順に自動で振り分け」または「ランダムに振り分け」でA〜Dリーグへ
5. **対戦・結果** → 「リーグ戦の対戦カードを作成する」
6. **進行表** を確認し、必要なら時間・コート・順番を調整
7. 参加者に共有するURLのQRコードを作り、印刷して受付や各コートに貼る

### 当日の受付で（参加者への案内）

配布・掲示する文面の例:

> **試合結果の入力方法**
> 1. QRコードを読み取ってサイトを開いてください
> 2. 「試合結果を入力する」をタップ
> 3. 自分のチームの試合を選び、スコアを入力
> 4. 確認画面が出たら内容を確かめて「登録する」
>
> 各試合、**勝ったチームの代表者1名**が入力してください。
> 間違えたときは入力し直せます。分からないときは本部までお越しください。

### 試合中（主催者）

- 基本は**待つだけ**です。参加者が入力すると、順位表・進行表・トーナメント表が自動更新されます
- 進行が遅れているコートは `/admin/matches` で「試合中にする」を押すと、参加者の進行表に「試合中」と出ます
- 入力ミスの申し出があったら `/admin/matches` で該当試合を探し、スコアを直して「結果を保存」
- 結果ごと取り消したい場合は「結果を取り消す」で待機中に戻せます
- 入力してくれない試合があれば、主催者が代わりに入力しても構いません（同じ画面で入力できます）

### 予選終了後（主催者）

1. `/admin/bracket` を開き、予選順位と各チームの進出先（A級/B級/C級のバッジ）を確認
2. 開始時刻を入力（空欄なら大会情報の設定値）して **「トーナメント表を作成」**
   - **全ての級が一度に作成されます**（A級・B級・C級を個別に作る必要はありません）
   - 作成後、各級の出場チーム数と試合数が画面下に表示されます
3. 参加者に「決勝トーナメントの組み合わせが出ました」とアナウンス
   - 参加者は `/bracket` の上部タブで自分の級を選びます
4. 以降は参加者が同じ手順で結果を入力すると、勝者が自動で次の試合へ進みます

### 大会終了後

- `/bracket` に優勝チームが表示されます
- データはSupabaseに残るので、後から順位表を見返せます
- 次の大会で使い回す場合は、`/admin/teams` でチームを入れ替えてから対戦カードを作り直してください

## 12. チーム数を変える場合

16チーム以外でも使えます。`/admin/tournament` で次を変更してください。

| 設定 | 説明 |
| --- | --- |
| リーグ数 | A から順に自動で作成・削除されます |
| 1リーグのチーム数（目安） | 表示用の目安です。実際の所属は「チーム・リーグ分け」で決まります |
| 順位別トーナメント（級） | 級ごとに「各リーグの何位から何位まで」を指定します |

変更後は **チームのリーグ分け → 対戦カードの作成 → トーナメント表の作成** の順にやり直してください。

### 級の設定例

| 大会の形 | 級の設定 |
| --- | --- |
| 全チームがトーナメントに出る（16チーム / 4リーグ） | A級 1〜2位 / B級 3位 / C級 4位 |
| 上位のみトーナメント | A級 1〜2位 のみ（B級・C級を削除） |
| 上位と下位の2部制 | A級 1〜2位 / B級 3〜4位 |
| 3チームずつ5リーグ | A級 1位 / B級 2位 / C級 3位 |

**同じ順位を複数の級に入れることはできません**（1チームが2つのトーナメントに出てしまうため）。
保存時にチェックが入り、重なっているとエラーメッセージが出ます。

### 出場チーム数が2の累乗でない場合

上位シードが**不戦勝（BYE）**で次のラウンドに入ります。
不戦勝の試合はトーナメント表に表示されないので、空欄の試合が並ぶことはありません。

動作を確認済みの構成例:

| 構成 | 予選 | トーナメント |
| --- | --- | --- |
| 16チーム / 4リーグ / A級1〜2位・B級3位・C級4位 | 24試合 | 14試合（A級8・B級3・C級3） |
| 16チーム / 4リーグ / A級のみ1〜2位 | 24試合 | 8試合 |
| 12チーム / 4リーグ / A級1〜2位・B級3位 | 12試合 | 11試合（B級4チーム） |

## 13. トラブル時の対処

| 症状 | 対処 |
| --- | --- |
| 「Supabase の環境変数が設定されていません」 | `.env.local`（本番はVercelの環境変数）の3つのキーを確認。設定後に開発サーバーを再起動 |
| 管理画面に入れない | `ADMIN_PASSWORD` が設定されているか確認。本番では変更後に再デプロイが必要 |
| 他の端末に結果が反映されない | 最大20秒待つと自動で更新されます。それでも変わらなければ画面を下に引っ張って再読み込み |
| 「対戦チームがまだ決まっていません」 | 前のラウンドの結果が未入力です。先にそちらを入力してください |
| 「同点では登録できません」 | ピックルボールは必ず勝敗が付くため、同点は登録できません |
| リーグが未設定のチームがある | `/admin/teams` の「登録順に自動で振り分け」を実行してください |
| 対戦カードを作り直したい | `/admin/matches` の「リーグ戦の対戦カードを作成する」（**入力済みのリーグ戦結果は消えます**） |
| 参加者が間違った試合に入力した | `/admin/matches` で両方の試合を修正してください |
| 会場のWi-Fiが不安定 | 参加者はモバイル回線でも使えます。最悪の場合は主催者が本部で代行入力してください |

## 14. 今後の拡張ポイント

MVPでは実装していませんが、**構造としては受け入れられるように作ってあります**。

| 機能 | 実装の入口 |
| --- | --- |
| 試合ごとのPINコード | `matches` に `pin` 列を追加し、`src/app/api/matches/[id]/report/route.ts` で照合する |
| 相手チームによる結果承認 | `matches` に `approval_status` を追加。`saveResult()` を「仮登録」と「確定」に分け、確定時だけ順位に反映する |
| 結果の変更履歴の表示 | すでに `match_events` に全履歴が入っているので、管理画面に一覧を出すだけ |
| 複数大会の同時運用 | `tournaments` は複数行を持てる構造です。`getState()` の「1件目を取る」処理をURLパラメータ指定に変える |
| 独自の同率ルール | `src/lib/standings.ts` の `compareBy()` に条件を追加し、`Tiebreaker` 型に名前を足す |
| 級ごとに別ルール（点数・時間） | `tournaments.bracket_tiers` のJSONに項目を足す。`src/lib/tiers.ts` の `normalizeTiers()` が入口 |
| 敗者トーナメント・順位決定戦 | `matches.loser_next_match_id` は既に敗者の進出先を扱えます（3位決定戦で使用中） |

### ソースコードの構成

```
src/
├─ app/
│  ├─ page.tsx                    参加者トップ
│  ├─ schedule/ standings/ bracket/ report/    参加者ページ
│  ├─ admin/                      管理画面
│  └─ api/                        書き込み用API（state / report / admin）
├─ components/                    UI部品（順位表・トーナメント表・結果入力など）
├─ lib/
│  ├─ standings.ts   ★順位計算（独立ロジック）
│  ├─ bracket.ts     ★トーナメント生成・勝ち上がり計算（独立ロジック）
│  ├─ tiers.ts       ★順位別トーナメント（級）の設定の検証・整形
│  ├─ schedule.ts    ★総当たり生成・時間とコートの割り当て
│  ├─ data.ts        サーバー側のDB操作
│  ├─ auth.ts        管理画面の認証
│  └─ useTournamentState.ts  リアルタイム取得フック
└─ middleware.ts                  管理画面の保護
```

★の3ファイルはDBに依存しない純粋な関数なので、ルールを変更したいときはここだけ読めば済みます。
