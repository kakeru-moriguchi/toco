# 組み合わせリセット

選択部門の予選と決勝を、それぞれ組み合わせ作成前へ戻す。

| 操作 | 削除するもの | 残すもの |
| --- | --- | --- |
| 対戦・結果 → 予選リーグの組み合わせをリセット | 予選の試合・確定結果・仮結果・承認待ち・進行表・試合履歴 | チーム・PIN・予選リーグ・所属・設定 |
| 決勝ラウンド → 決勝ラウンドの組み合わせをリセット | 全級の本戦・3位決定戦・決勝総当たり・単発敗者戦（取消済みも含む）・結果・仮結果・進行表・試合履歴、決勝専用リーグ | 予選の試合と結果・チーム・PIN・予選リーグ・所属・設定 |

確認画面に部門名と対象試合数、削除範囲、元に戻せないことを表示する。APIは管理者認証に加え、大会・部門IDの指定と、確認した部門IDの一致を要求する。部門選択が変わっていた場合はリセットしない。

決勝が残る状態で予選をリセットすると、予選順位と決勝の整合性が崩れるため、先に決勝をリセットする案内を返す。予選リセットが自動で決勝を消すことはない。

大会・部門IDで対象を絞り込み、共通の大会phaseには触れない。既存の決勝削除処理はエラーを確認する共通関数へ移し、リセット後の再作成は既存の生成処理を利用する。SQL・テーブル変更は不要。

## 検証

- ローカルPostgreSQLに2大会・各2部門を用意し、実際の管理APIから確認。
- 未認証、確認なし、確認部門の不一致、対象指定なしを拒否。
- 決勝が残る予選リセットを拒否し、データが消えない。
- 決勝リセットで総当たりと取消済み敗者戦も消え、予選結果・予選履歴が残る。
- 予選リセットで承認待ちを含む予選試合と履歴が消え、チーム・PIN・リーグ所属が残る。
- 別大会・別部門の試合・リーグ・履歴、全大会・部門の設定が変わらない。
- 未作成状態への再実行が成功し、その後に予選・決勝を再作成できる。
- ローカルブラウザの390px相当で両ボタンを確認。ページの横はみ出しなし。予選を未作成へ戻した後も20チームのPIN設定が残り、決勝リセット後も別部門の予選20試合が残る。

`npm test` は29件成功。型チェック・Lint・本番ビルドも実施。本番データのリセットは検証に使用していない。

削除は既存のREST操作を順に実行する。通信障害などで途中失敗した場合はエラーを返すが、複数テーブルにまたがる全操作のロールバックは行わない。残った決勝専用リーグなどは再実行で片付けられる。複数管理者の同時操作を防ぐDBロックは今回追加していない。
